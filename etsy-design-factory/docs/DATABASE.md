# DATABASE

PostgreSQL is the single source of truth. This document describes the
schema at the level implemented by `backend/app/db/models/*.py` and
generated by Alembic migrations in `backend/migrations/`.

## Conventions

- Primary keys: `UUID` (`uuid4`, generated app-side so IDs exist before
  insert and can be referenced across a task chain before commit).
- Timestamps: `TIMESTAMPTZ`, always UTC, `created_at` on every table.
  Mutable-status tables also have `updated_at`.
- Structured "DNA" / score / config payloads use a portable JSON type:
  `sqlalchemy.types.JSON().with_variant(postgresql.JSONB, "postgresql")`.
  This renders as real `JSONB` (indexable, queryable with `->>`, GIN
  indexable) on Postgres in production, and as `JSON` on SQLite in the test
  suite, so the same models run in both without a live Postgres instance.
- Money: `NUMERIC(10,4)` USD. Never floats for cost.
- Append-only tables (see `DOMAIN_MODEL.md` invariant 1) have no
  `updated_at` and no update path in the ORM layer beyond status-only
  tables noted below.

## Tables

### collections
`id, name, thesis, target_aesthetic, target_customer_hypothesis,
palette_boundaries JSONB, medium, subject_families JSONB,
composition_diversity_requirements JSONB, target_design_count,
experimental_variables JSONB, status, mode
(DISCOVERY|PRODUCTION), created_at, updated_at`.
Index: `(status, mode)`.

### design_genomes
`id, design_lineage_id, version, parent_genome_id (nullable FK →
design_genomes.id), derived_from_version_id (nullable FK →
design_genomes.id), generation_number, collection_id (nullable FK),
subject_dna JSONB, style_dna JSONB, composition_dna JSONB, palette_dna
JSONB, texture_dna JSONB, medium_dna JSONB, era_dna JSONB, mood_dna JSONB,
detail_dna JSONB, print_dna JSONB, commercial_dna JSONB, mutation_map
JSONB (nullable — which fields were kept vs. mutated and by how much),
created_by (enum: SYSTEM_DISCOVERY|SYSTEM_MUTATION|HUMAN_EDIT),
created_at`.
Indexes: `(design_lineage_id)`, `(parent_genome_id)`, `(collection_id)`.
GIN index on `style_dna`, `palette_dna` for similarity pre-filtering.

### concepts
`id, design_genome_id (FK), collection_id (FK), production_mode
(DISCOVERY|PRODUCTION), planned_candidate_count, gate_status
(PENDING|PASSED|REJECTED), gate_reasoning, created_at`.

### generation_jobs
`id, concept_id (FK), attempt_number, provider, model, compiled_prompt,
params JSONB, status, idempotency_key (unique), created_at, updated_at`.

### generation_candidates
`id, generation_job_id (FK), concept_id (FK), design_genome_id (FK),
storage_key, width_px, height_px, checksum_sha256, perceptual_hash,
status (state machine — see DOMAIN_MODEL.md), is_repair, repair_attempt_id
(nullable FK), created_at, updated_at`.
Indexes: `(status)`, `(concept_id)`, `(perceptual_hash)`.

### evaluations
`id, generation_candidate_id (FK), scored_by (provider/model id),
aesthetic JSONB, originality JSONB, commercial_potential JSONB,
technical_quality JSONB, printability JSONB, collection_fit JSONB,
diversity JSONB, overall_pass (bool), created_at`.
Each `*` JSONB column is `{value, confidence, reasoning, problems[]}`.
Append-only — re-scoring inserts a new row.

### failure_records
`id, generation_candidate_id (FK), failure_class
(TERMINAL_FAILURE|REPAIRABLE_FAILURE|PROMISING|ACCEPTED), detected_problems
JSONB, diagnosis_reasoning, diagnosed_by, created_at`.

### repair_attempts
`id, failure_record_id (FK), genome_delta JSONB, prompt_delta, provider,
model, resulting_candidate_id (nullable FK → generation_candidates),
outcome (PENDING|IMPROVED|NO_IMPROVEMENT|FAILED), cost_event_id (nullable
FK), created_at`.

### experiments
`id, hypothesis, design_genome_id (FK, nullable), collection_id (nullable
FK), variables_tested JSONB, provider, model, params JSONB,
output_candidate_ids JSONB (array of UUID), scores_summary JSONB,
winner_candidate_id (nullable FK), failure_summary (nullable),
cost_usd NUMERIC, commercial_outcome JSONB (nullable, filled later by
commercial_learning), created_at`.

### artworks
`id, generation_candidate_id (FK, unique), design_genome_id (FK),
collection_id (FK), master_storage_key, master_width_px,
master_height_px, approved_at, approved_by (user identifier), sku,
created_at`.

### print_exports
`id, artwork_id (FK), ratio (enum: "2:3","3:4","4:5","5:7","11:14","A"),
target_long_edge_px, actual_width_px, actual_height_px, storage_key,
upscaled (bool), upscale_provider (nullable), created_at`.
Unique: `(artwork_id, ratio)`.

### mockups
`id, artwork_id (FK), template_id, storage_key, created_at`.

### etsy_listing_packages
`id, artwork_id (FK, unique), title_concepts JSONB, description_data
JSONB, keyword_candidates JSONB, tags JSONB, style, subject, palette,
orientation, collection_id (FK), internal_sku, print_export_ids JSONB,
mockup_ids JSONB, published_at (nullable), external_listing_id (nullable),
created_at`.

### commercial_observations
`id, artwork_id (nullable FK), design_genome_id (nullable FK),
external_listing_id (nullable), source (e.g. "etsy"), metric_name,
metric_value NUMERIC (nullable — NULL means "not reported", never
fabricated), observed_at, ingested_at`.

### creative_families
`id, name, defining_dna_signature JSONB (ranges/sets over DNA fields,
not literal genomes), status (CHALLENGER|CHAMPION|RETIRED),
member_genome_ids JSONB, performance_summary JSONB (nullable, populated
only from real `commercial_observations`), created_at, updated_at`.

### daily_production_plans
`id, plan_date (date, unique), target_final_designs, portfolio_allocation
JSONB (`{PROVEN, GROWING, EXPERIMENTAL, WINNER_MUTATION, WILDCARD}` →
int), collections JSONB (array of `{collection_id, slots, mode}`),
experimental_slots, winner_mutation_slots, production_slots,
budget_cap_usd NUMERIC, policy_version, rationale, created_at`.

### cost_events
`id, provider, model, operation, tokens_input (nullable), tokens_output
(nullable), generation_cost_usd NUMERIC, processing_cost_usd NUMERIC,
project (default "etsy-wall-art"), collection_id (nullable FK),
design_genome_id (nullable FK), generation_candidate_id (nullable FK),
is_simulated (bool, true for fake-provider test runs), created_at`.
Index: `(created_at)`, `(collection_id)`.

### provider_health_logs
`id, provider, operation_type, success (bool), latency_ms, error_class
(nullable), circuit_state (CLOSED|OPEN|HALF_OPEN), created_at`.

### approvals
`id, generation_candidate_id (FK), action (APPROVE|REJECT|MORE_ORIGINAL|
CLOSER_TO_COLLECTION|CHANGE_COMPOSITION|CHANGE_PALETTE|MORE_TEXTURE|
LESS_TEXTURE|MORE_MINIMAL|MORE_DETAILED|CREATE_VARIATIONS), actor,
resulting_genome_id (nullable FK — set when the action mutates the
genome and re-queues), notes (nullable), created_at`.

## Migration strategy

Alembic, one linear history under `backend/migrations/versions/`. Every
schema change is a new revision; no hand edits to applied migrations.
`alembic upgrade head` is required in CI and in the Docker entrypoint
before the API/workers start serving traffic.

## Why not overwrite

`DesignGenome`, `Evaluation`, `FailureRecord`, `RepairAttempt`,
`Experiment`, `CommercialObservation`, `CostEvent`, and `ProviderHealthLog`
rows are never updated after insert. This is what makes "never overwrite
DesignGenome versions / prompts / evaluations / generations / repair
history / experiments / commercial observations" (mission requirement) a
database-enforced property rather than a convention: the ORM layer for
these entities exposes no `update`, only `create`.
